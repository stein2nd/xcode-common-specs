# Xcode Common Specs - Viewport Integrity

## 目的

* UI 上に表示されたインタラクティブ要素は、必ずユーザーの標準的な操作によって到達・操作できること、を非機能要件として固定する。
* 起動 / 回転 / 分割 / ウィンドウ・リサイズで、レイアウトの中間状態をユーザーに露出させない。
* 本別紙は、iOS / iPadOS を基準とし、Android 展開時は、同等の到達性を保証する。macOS は、ウィンドウ・リサイズを Viewport 変更とみなす。Windows 11 は、対象外とする。

## 原則

Viewport Integrity は、次の4つで構成する。個別画面の UI 仕様は、この語彙で書く。

| 原則 | 一言 |
| --- | --- |
| Reachability (到達性) | 見えている UI 要素には、必ず到達できる |
| Layout Stability (安定) | 起動・回転・サイズ変更で、予期せず移動しない |
| Content Integrity (欠落防止) | 操作対象がクリップされて消えない |
| Interaction Integrity (操作の一貫) | ジェスチャーが意図しない親 View に奪われない |

## Reachability (到達性)

* 画面幅を超えるコンテンツは、スクロール可能である。コンテンツ幅と Viewport 幅は、分離して設計する。
* スクロール可能な方向は、視覚的に推測できる (次項目の覗き見え、フェード、インジケータのいずれか)。
* 始端にスクロールしたとき、最初の項目が完全に表示される。
* 終端にスクロールしたとき、最後の項目が完全に表示される。Safe Area や Home Indicator に隠れない。
* 操作対象は、Safe Area 内で操作可能である。
* 横スクロールと縦スクロールは、競合して操作不能にならない。入れ子にする場合は、どちらが勝つかを画面仕様に書く。
* iPhone の Dynamic Island / Home Indicator によって、操作不能領域を作らない。
* iPad の Split View / Stage Manager 等で Viewport が狭くなっても、到達性を落とさない。
* iPad を、最初から「iPhone の画面を拡大したもの」として設計しない。広い Viewport は、分割や余白の再構成に使う。
* Dynamic Type で文字が大きくなっても、インタラクティブ要素への到達性を落とさない。
* Android では、Dynamic Island を模倣しない。同等の到達性は、システムバー / ジェスチャー・ナビゲーション / ディスプレイ・カットアウト / マルチウィンドウで保証する。

横に並ぶチップが Viewport を超える例:

```
コンテンツ幅 ≠ Viewport 幅。終端までスクロールできる。

┌─────────────────────────────┐
│ Readme  情報  依存関係  … → │
└─────────────────────────────┘
        ⇅ horizontal scroll

終端:
┌─────────────────────────────┐
│           統計  GitHub      │
└─────────────────────────────┘
                    ↑
              最後の項目が完全に表示
```

## Layout Stability (安定)

* 起動時に、レイアウトの中間状態を表示しない。
* Orientation 変更時に、レイアウトの中間状態を表示しない。
* Safe Area 確定前の暫定座標を、ユーザーに露出しない。
* コンテンツの左寄せ → 中央寄せ等の自動補正を、視認可能な形で発生させない。
* Viewport 変更後、一度確定したレイアウトが不必要に移動しない。
* 横幅変更によって、コンテンツが一瞬クリップされない。
* Scroll Position が、意図せず変更されない (コンテンツの同一性を保つ場合)。
* ユーザーに見せる最初のフレームは、確定後のレイアウトである。サイズが分かっている骨格 (プレースホルダ) は、確定フレームとみなしてよい。Geometry 待ちの空白フラッシュを必須にはしない。誤配置のフレームを出さないことが目的である。
* macOS では、ウィンドウ・リサイズを Orientation 変更と同等の Viewport 変更として扱う。

## Content Integrity (欠落防止)

* インタラクティブなコンテンツが、到達手段なしにクリップされて消えない。
* 意図したオーバーフローは、Reachability のスクロールで解消する。オーバーフローを「見切れ」のまま放置しない。
* 末尾の項目は、余白を含めて完全に描画できる幅を確保する。

## Interaction Integrity (操作の一貫)

* 子の横スクロールを、親の縦スクロールが奪って操作不能にしない。
* 戻るスワイプと横スクロールが重なる画面は、優先するジェスチャーを画面仕様に書く。
* タップ対象が、わずかなパンでスクロールに飲まれて押せなくならない。

## テスト

* 複数の Viewport (コンパクト / レギュラー、Portrait / Landscape、iPad Split View の狭幅) で SnapshotTesting する。
* 横スクロールを持つコンポーネントは、始端と終端で「最初 / 最後の項目の frame が可視矩形に完全包含される」ことを自動テストする。
* 起動直後と Orientation 変更直後は、Simulator の簡便確認で中間状態が出ないことを見る。中間状態の自動検出は必須にしない。
* ひな型のケース ID は、[`TEST_RESULTS.md`](./TEST_RESULTS.md) に置く。
